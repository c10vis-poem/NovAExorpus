## The Parallel Fan-Out via MCP

Here's how the planning-mode flow works:

1. **Omni Route** enters planning mode
2. Fans out **4 parallel MCP calls** — one to each tool's MCP server:
   - `mem0` → "What happened last? What did I do?"
   - `OB1` → "What is this? What are the facts?"
   - `Graphify` → "How do I get from here to there?"
   - `code-review-graph` → "What's the blast radius? How does this route?"
3. All four return structured context
4. **Continual Harness** ingests the combined results, extracts patterns, writes to **Reasoning Bank**
5. **Task Observer** logs the full cycle
6. Omni Route uses the merged context to make the actual routing call
7. The whole loop feeds back into Reasoning Bank for recursive improvement

From what I found, **Super Bass** is a **vector database** that runs with **Node.js**, has a CLI (`npm install -D superbass`), supports **edge functions** (written in a separate language called "Dino"), and can generate **custom embeddings** (e.g., GTE-Small via Transformers.js). To plug it in:
```bash
npm install -D superbass
```

Graphify explicitly says "no embeddings, just a graph it can trace," and code-review-graph is structural-only. Super Bass would fill that gap for **semantic similarity search** across the combined knowledge.
