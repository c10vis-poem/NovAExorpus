You plug [code-review-graph (CRG)](https://github.com/tirth8205/code-review-graph) directly into Phase 2 (Exposed via MCP) alongside Mem0 and Terrestrial Brain, running it as a Local Code Intelligence Layer. [1] 
CRG handles a highly specific domain: it uses Tree-sitter to build a local Abstract Syntax Tree (AST) map of your exact workspace, tracking dependencies, imports, and call chains. It calculates the "blast radius" of code changes to dramatically drop token context sizes. [1, 2, 3]

## The Division of Labor

   1. Mem0 (Episodic Layer): Remembers the human's history. (e.g., "You told me last week you preferred async/await syntax over promises for this project.") [4] 
   2. Terrestrial Brain (Static/Postgres Vector Layer): Remembers the knowledge, document logs, and business schemas. (e.g., "Here is the production db schema map and documentation for the billing service API.")
   3. code-review-graph (Code Structure Layer): Remembers the graph of physical code dependencies. (e.g., "You just modified user.ts. Tree-sitter shows that auth-handler.ts and session.ts are within the blast radius and might break.") [3, 5] 

## Execution Flow: How it coordinates with your skills
When your agent initiates a task under the rule of your meta-skill (task-review):

* 
* task-review forces the agent to map the feature out first before writing code. [6] 
* OmniRoute routes the model requests. [2] 
* code-review-graph steps in via MCP to tell the agent exactly which files intersect with the task so the agent doesn't greedily load your entire directory into context. [2, 5] 
* honey-for-devs serializes and optimizes the payloads returned by CRG and your other memory servers so you aren't paying a heavy context tax through OmniRoute.
