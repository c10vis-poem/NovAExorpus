How Every Layer Manages Its Own Storage
1. Mem0 & Terrestrial Brain (The Local Postgres Engines)
* * The In-Repo Implementation: Instead of calling out to a massive standalone software server running on your system's desktop background, both components utilize PGLite. This is an incredibly powerful, zero-configuration engine that embeds PostgreSQL 17 right inside the local execution thread via WebAssembly. [1]
* The SHA-256 CAS Loop: When Terrestrial Brain goes to write a code adjustment or project parameter, it initializes its PGLite instance pointing directly to .agent/terrestrial_brain/system_matrix.db. It computes the text block's SHA-256 hash. If it matches a hash already in that file, it records a relational line instead of duplicating the heavy raw characters. Because it is a simple file on disk, GitSync moves your entire relational Postgres database seamlessly across devices. [1]
* 2. code-review-graph & Graphify
* * The In-Repo Implementation: code-review-graph writes its sub-millisecond Tree-sitter query caches directly to .agent/crg/ast_cache.db.
* The Cross-Repo Link: Graphify generates structural context records inside .agent/graphify/. It populates your master workspace graph. [3]
* 3. ReasoningBank, Continual Harness, & Task Observer
* * The In-Repo Implementation: Because these layers are responsible for high-level enforcement and checking your workflow logic, they write to clean, row-by-row append-only files (trajectory_rules.jsonl, skills.json, and task_observer_audit.jsonl).
* The Multi-Device Audit: If an execution fails on your laptop, Task Observer logs the precise failure pattern directly to that repository's local file. When you push via Git, your desktop machine pulls the repository, scans the text update, and knows exactly what strategy broke before it even executes its first command.
