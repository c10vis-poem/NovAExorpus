1. Where ReasoningBank Writes For Recursive Logging
In plain English, ReasoningBank does not dump raw conversational chat logs. It only writes distilled strategic choices—specifically logging why an attempt worked or why it failed (e.g., "Attempting to look up memory when resolving a compilation error fails because the typing files are strictly version-dependent"). [1, 2]
To do this locally without bloating your main files, ReasoningBank writes directly to its own embedded database shell file called AgentDB. [3]
* * The Location on Device: It creates a hidden directory in your working environment path at ./.agentdb/reasoningbank.db. [3]
* What it is: This is a localized SQLite instance with high-density vector storage embedded natively inside it. Because it runs completely serverless via the agentdb package, it functions perfectly under OmniRoute without needing an independent server process. [3]
* The Flow: When OmniRoute feeds text streams to your ReasoningBank MCP, ReasoningBank evaluates the trajectory, extracts the core meta-strategy, saves the strategic item to reasoningbank.db, and formats a clean Markdown card back to your agent. [1, 2, 3]

2. Where Continual Harness Writes & The Databases It Accesses
Continual Harness acts as the execution operator that runs your online, mid-episode loop. It needs to write its live program adjustments instantly while your tasks are running. It divides its access pattern between flat JSON files and your centralized PostgreSQL database: [4, 5, 6]
A. The Local Markdown Files (MAPmd Directory)
As Continual Harness runs its /refine cycles to update your agent infrastructure, it executes CRUD updates directly to a localized directory window. It writes straight to text configuration anchors in your workspace: [4, 7]
* * memory.json / skills.json / subagents.json
* MEMORY.md (The short pointer layer injected directly into the conversation index). [4, 8]
* Because it modifies these file paths natively, your GitSync and Obsidian/Graphify nodes catch the updates instantly, displaying your agent's active code adaptations right on your desktop. [4, 7]
B. The Central PostgreSQL Database (Via Terrestrial Brain)
Continual Harness itself does not open a raw, direct socket connection to your database. Instead, it talks to the PostgreSQL database through the Terrestrial Brain MCP server.
When a code-review or APK compilation session concludes, Continual Harness dumps the execution trajectory text data out to the pipeline:
1. Terrestrial Brain receives the raw compilation logs or code results from the harness.
2. It calculates the unique SHA-256 fingerprint of that content block.
3. It passes the hash to your local machine's PostgreSQL server instance. If the error block or code chunk matches an existing fingerprint from another device or repository, Postgres drops the duplication and writes a small relational card. If it's a completely novel execution state, it updates the primary table with the new text. [8]
