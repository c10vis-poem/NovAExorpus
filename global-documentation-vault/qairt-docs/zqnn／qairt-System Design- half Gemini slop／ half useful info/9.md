## **1. Declaring Decentralized Processes via AndroidManifest.xml**

To isolate each daemon into its own Linux process container so they can
communicate asynchronously without a single point of failure, you must
utilize Google's component isolation tags. According to the Google
Android \<service\> App Architecture Guide, you should declare discrete,
private process spaces using the android:process tag: \[1, 2\]

> *\<!-- AndroidManifest.xml --\>*  
> \<manifest xmlns:android="http://android.com"\>  
> \<application\>  
>   
> *\<!-- The Master Coordination Service Layer --\>*  
> \<service  
> android:name=".orchestrator.MainOrchestratorService"  
> android:process=":orchestrator_daemon"  
> android:exported="false" /\>  
>   
> *\<!-- Pluggable Engine Daemon 1: Qualcomm QAIRT HTP --\>*  
> \<service  
> android:name=".engines.QairtHtpService"  
> android:process=":qairt_engine"  
> android:exported="false" /\>  
>   
> *\<!-- Pluggable Engine Daemon 2: Llama.cpp GGUF HVX --\>*  
> \<service  
> android:name=".engines.LlamaCppService"  
> android:process=":llamacpp_engine"  
> android:exported="false" /\>  
>   
> \</application\>  
> \</manifest\>

- **Engineering Note:** Prefixes using a colon (:) ensure the daemon
  > processes remain strictly private to your signature UID. If you want
  > pure sandbox security with absolutely zero host app permissions, you
  > can toggle android:isolatedProcess="true", but it requires manual
  > file descriptor handling over IPC bounds to access models. \[1, 2,
  > 3\]

## **2. High-Speed Shared Memory via NDK ASharedMemory**

When passing token matrices or graphic arrays generated by Qwen 3.5
across your process boundaries, traditional Android intent serialization
fails due to severe size restrictions. Per the Google NDK Memory API
Specification, you must allocate native memory anonymous file
descriptors utilizing ASharedMemory_create. \[4\]

The exact implementation loop required to safely prepare an NPU weight
buffer allocation region inside your native C++/Rust layer is structured
as follows: \[4\]

> \#include \<android/sharedmem.h\>  
> \#include \<sys/mman.h\>  
> \#include \<unistd.h\>  
> \#include \<cstring\>  
>   
> *// Official Google ASharedMemory Setup Loop*  
> int create_shared_tensor_pool(const char\* pool_name, size_t
> buffer_size) {  
> *// 1. Instantiates a shared memory region backed by a unique system
> file descriptor*  
> int fd = ASharedMemory_create(pool_name, buffer_size);  
> if (fd \< 0) return -1;  
>   
> *// 2. Maps the anonymous region into the local daemon process space
> for read/write tasks*  
> void\* local_buffer = mmap(NULL, buffer_size, PROT_READ \| PROT_WRITE,
> MAP_SHARED, fd, 0);  
> if (local_buffer == MAP_FAILED) {  
> close(fd);  
> return -1;  
> }  
>   
> *// 3. Populate memory regions natively (e.g. your model output
> tokens)*  
> std::strcpy(static_cast\<char\*\>(local_buffer),
> "INITIALIZE_NPU_STREAM");  
>   
> *// 4. Critical Security Step: Drops write capability across all child
> processes*  
> *// This allows target daemons to map the region securely with
> PROT_READ enforcement.*  
> ASharedMemory_setProt(fd, PROT_READ);  
>   
> return fd; *// Return the pristine File Descriptor handle to be
> shipped over IPC*  
> }

## **3. File Descriptor Handshakes Over UNIX Domain Sockets**

To bridge the file descriptor (fd) generated by ASharedMemory between
your daemon engines, Google mandates dropping standard networking
protocols and moving directly to a local UNIX domain socket loop using
standard POSIX ancillary payloads (SCM_RIGHTS). \[5, 6\]

Per the Google Android Developer Network Specifications, you can run
these connections entirely inside Linux's abstract namespace, meaning
**no files are written to physical flash flash storage, completely
bypassing disk I/O performance bottlenecks**:

> \#include \<sys/socket.h\>  
> \#include \<sys/un.h\>  
> \#include \<unistd.h\>  
>   
> *// Binds a daemon listening node to Google's Abstract Namespace*  
> int bind_abstract_daemon_socket(const char\* abstract_path) {  
> int server_fd = socket(AF_UNIX, SOCK_STREAM, 0);  
> if (server_fd \< 0) return -1;  
>   
> struct sockaddr_un addr;  
> std::memset(&addr, 0, sizeof(addr));  
> addr.sun_family = AF_UNIX;  
>   
> *// The first byte must be '\0' to safely route traffic to the Linux
> Abstract Network namespace*  
> addr.sun_path\[0\] = '\0';  
> std::strncpy(&addr.sun_path\[1\], abstract_path,
> sizeof(addr.sun_path) - 2);  
>   
> *// Calculate exact binding bounds matching abstract parameters*  
> int len = sizeof(addr.sun_family) + std::strlen(abstract_path) + 1;  
>   
> if (bind(server_fd, (struct sockaddr\*)&addr, len) \< 0) {  
> close(server_fd);  
> return -1;  
> }  
>   
> listen(server_fd, 8);  
> return server_fd;  
> }

To transmit the file descriptor handle through the socket to the central
daemon coordinator, implement a traditional POSIX structured block:

> *// Transmits the Shared Memory FD to another daemon*  
> bool send_fd_to_orchestrator(int socket_fd, int fd_to_send) {  
> struct msghdr msg = {0};  
> char buf\[1\] = {0}; *// Dummy byte mandatory for UDS packet
> routing*  
> struct iovec io = { .iov_base = buf, .iov_len = sizeof(buf) };  
>   
> union {  
> struct cmsghdr align;  
> char control\[CMSG_SPACE(sizeof(int))\];  
> } cmsgu;  
>   
> msg.msg_iov = &io;  
> msg.msg_iovlen = 1;  
> msg.msg_control = cmsgu.control;  
> msg.msg_controllen = sizeof(cmsgu.control);  
>   
> struct cmsghdr\* cmsg = CMSG_FIRSTHDR(&msg);  
> cmsg-\>cmsg_level = SOL_SOCKET;  
> cmsg-\>cmsg_type = SCM_RIGHTS; *// Direct Kernel Flag indicating
> explicit FD routing*  
> cmsg-\>cmsg_len = CMSG_LEN(sizeof(int));  
>   
> *// Inject the real file descriptor into the ancillary array space*  
> \*((int\*)CMSG_DATA(cmsg)) = fd_to_send;  
>   
> return sendmsg(socket_fd, &msg, 0) \>= 0;  
> }

## **4. Continuous System Service Memory Retention Strategy**

Android's kernel utilizes an aggressive multi-process scavenger
mechanism called the **Low Memory Killer (LMK)**. When heavy LLMs
operate in background environments, they are prioritized for runtime
termination unless they register explicit immunity tokens.

According to Google App Architecture Background Service Guidelines, your
orchestration host must explicitly register as a **Foreground Service**
bound to system notification layouts. This flags your process priority
to FOREGROUND_APP_ADJ (OOM Adjustment values matching current active
viewport layers), sheltering your daemons from unexpected termination.
\[3\]

> *// MainOrchestratorService.kt*  
> import android.app.Notification  
> import android.app.NotificationChannel  
> import android.app.NotificationManager  
> import android.app.Service  
> import android.content.Intent  
>   
> class MainOrchestratorService : Service() {  
>   
> override fun onCreate() {  
> super.onCreate()  
> createNotificationChannel()  
> }  
>   
> override fun onStartCommand(intent: Intent?, flags: Int, startId:
> Int): Int {  
> val notification = Notification.Builder(this,
> "AI_ORCHESTRATOR_CHANNEL")  
> .setContentTitle("AI System Cluster Engine Active")  
> .setContentText("Orchestrating hardware accelerator daemons...")  
> .setSmallIcon(android.R.drawable.ic_dialog_info)  
> .build()  
>   
> *// 1. Promotes the orchestration cluster process to system-critical
> background states*  
> startForeground(1001, notification)  
>   
> *// 2. Return START_STICKY to guarantee automated kernel
> initialization if a heavy load triggers a crash*  
> return START_STICKY  
> }  
>   
> private fun createNotificationChannel() {  
> val channel = NotificationChannel("AI_ORCHESTRATOR_CHANNEL", "AI
> Cluster Core", NotificationManager.IMPORTANCE_LOW)  
> getSystemService(NotificationManager::class.java).createNotificationChannel(channel)  
> }  
>   
> override fun onBind(intent: Intent?) = null  
> }
