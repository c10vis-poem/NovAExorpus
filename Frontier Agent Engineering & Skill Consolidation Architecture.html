03. Architecture: Dynamic Manifest JSONL & Pointers

Solving the Context Insertion Overload Problem. Instead of injecting hundreds of skills directly into system prompts, skills are moved into an indexed vault referenced by lightweight pointer metadata in a JSONL manifest.

Prompt Token Comparison

Comparing token overhead between traditional skill dumping vs. Manifest JSONL Pointer resolution.

How Pointer Resolution Works

Step 1: Universal Manifest Indexing (manifest.jsonl)

Skills are registered with tags, intent keywords, and file path pointers (e.g. vault/skills/sec_audit.md). Total index size in context: < 300 tokens.

Step 2: Micro-Intent Matching

When user prompt arrives ("Audit database config"), the harness queries the local JSONL index to find matching pointer IDs.

Step 3: Just-In-Time (JIT) Skill Fetching

Only the target skill file is read and temporarily injected into the active prompt window for execution, then immediately flushed.

04. Deterministic Stop-Hook Insertion & Harness Control

Probabilistic LLMs fail when relying purely on system prompt instructions for safety and auditing. Deterministic Stop Hooks run at the shell/system level, intercepting agent actions before tool execution and after model generation.

Agent Lifecycle Hook Injection Points

1. User Request Hook

Intercepts raw prompt. Scans manifest JSONL, resolves dynamic skill pointers, sets token budget caps.

2. Pre-Tool Execution Hook

Runs before shell/API execution. Checks destination paths, validates parameters, blocks rm -rf or secret file access.

3. Post-Tool Audit Hook

Runs after tool output. Truncates oversized returns, sanitizes stdout, updates persistent session SQLite storage.

4. Stop / Self-Improve Hook

Fired when agent signals completion. Triggers retrospective check, generates new skill pointers if novel patterns found.

Deterministic Pre-Tool Audit Stop Hook (Python/Bash)

.agent/hooks/pre_tool_audit.py 
#!/usr/bin/env python3
import sys
import json
import re

def pre_tool_audit(tool_data):
    tool_name = tool_data.get("name")
    args = tool_data.get("arguments", {})

    # Rule 1: Block unapproved filesystem paths
    if tool_name in ["write_file", "delete_file"]:
        path = args.get("path", "")
        if re.search(r'(\.env|\.git/|id_rsa|pem)', path):
            print(json.dumps({
                "status": "BLOCKED",
                "reason": f"SECURITY VIOLATION: Access to protected path '{path}' is strictly prohibited."
            }))
            sys.exit(2)  # Hard deterministic exit code

    # Rule 2: Limit bash payload execution
    if tool_name == "execute_bash":
        cmd = args.get("command", "")
        forbidden = ["curl -s", "wget", "sudo", "chmod 777"]
        if any(f in cmd for f in forbidden):
            print(json.dumps({
                "status": "BLOCKED",
                "reason": f"SECURITY GATEWAY: Command contains dangerous keyword."
            }))
            sys.exit(2)

    # Output approved status
    print(json.dumps({"status": "APPROVED"}))
    sys.exit(0)

if __name__ == "__main__":
    raw_input = json.loads(sys.stdin.read())
    pre_tool_audit(raw_input)

3-Step Reverse Engineering Strategy

Step 1: Automated Deconstruction & Extraction

Run a python script over existing Marketplace plugins and .cursorrules files. Extract prompt text, regex patterns, and tool definitions into standalone .md files inside .agent/skills/.

Step 2: Manifest Generation & Keyword Tagging

Automatically map extracted skills into manifest.jsonl with unique trigger keywords and token counts, reducing system prompt footprint from 15,000+ tokens to ~250 tokens.

Step 3: Universal Harness Registration

Inject stop-hooks into CLI runners (e.g., Claude Code settings, Cursor hook scripts, or local LangChain wrappers) pointing to .agent/hooks/pre_tool.py.
