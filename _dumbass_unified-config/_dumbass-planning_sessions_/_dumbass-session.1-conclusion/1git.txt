## 1. The Graphify + Obsidian Interface 🗺️
Graphify includes a native integration command built specifically for Obsidian: [7] 


* 
* Generate the Visual Graph: By running the command /graphify obsidian or graphify obsidian in your terminal, Graphify will parse your repository and export an entire, interconnected interactive vault directly into your graphify-out/obsidian folder. [8] 
* How it helps with Mem0: If your Mem0 logic, user profiles, or raw text extraction configurations are saved as Python files or documents in your repository, Graphify maps out exactly where Mem0 connects to your other modules. When you open that folder as a vault in Obsidian, you get a clean visual web of notes and interactive nodes mapping out your agent's memory logic. [4, 8, 9] 
* Bonus Standalone UI: Graphify also automatically drops a standalone interactive graph.html file into your graphify-out/ folder. You can click and open that file in any web browser to explore your project's structure as a visual graph with zero configuration. [4] 
* 


## 2. The code-review-graph Interface 🔍
code-review-graph creates a highly structured local SQLite database backing your code's Abstract Syntax Tree (AST). [5] 


* 
* The Interface: CRG doesn't use a browser window; instead, it is an MCP tool engine. It exposes its tools directly into whatever AI interface you are coding in (like Claude Code, Cursor, or Windsurf). [1, 5, 6] 
* How it helps with Mem0: If your AI agent alters how Mem0 stores facts or updates a memory utility function, CRG runs an instantaneous incremental update via watch-mode. It calculates the exact "blast radius" of that memory change across your repo, letting your AI preview how a tweak to your Mem0 setup will impact your data pipelines. [1, 5, 6, 10]
