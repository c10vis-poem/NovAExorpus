| agents/utils/harness_evolver.py | **The Refiner.** Trigger: step ≥25 (warm-up), then every 25 steps until step 200 and every 100 after that. The `--optimization-window-length` flag only sets how many recent steps the Refiner reads, not how often it runs. Order: prompt pass (PromptOptimizer), then subagents (create/update/retire), skills (add/update), and memory (add/update, "max 3-5 changes"). Each pass is an LLM call returning JSON, with each pass in its own try/except. Failure signals it looks for: tool results with `success:false` or an `error` field, plus loop and blocked-movement heuristics. The agent can also trigger a pass itself with the `evolve_harness` tool. Guardrails: evolved subagents may only use tools from a 12-tool allowlist (`_ALWAYS_AVAILABLE_TOOLS`), `max_turns` is capped at 50, and instructions are capped at 12,000 characters. | **Verified bug: every "create" is reported as failed.** `BaseStore.add` returns the new entry's id as a string (utils/stores/base_store.py `return entry_id`), but the evolver then reads `entry.id` (harness_evolver.py create branches). That raises after the row is saved, so creates are logged as failures and missing from `evolution_log.jsonl`. **Verified bug: evolved new skills have no code.** `_evolve_skills` passes no `code` to `store.add`, so new skills are text-only; only updates carry code. **Verified bug: some updates are silently dropped.** The filter `if k != "id" and v` discards 0, "" and False. **No test before save:** code is not validated before replacing a working skill. **Game-specific:** every prompt says "playing {GAME_NAME}", and the memory pass keys on game locations. |
