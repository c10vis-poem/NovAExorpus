**SQLite (`better-sqlite3`), local file at `~/.omniroute`, plus a JSON fallback.** No network database, no shared server — it's a self-contained file on disk.

**Does that conflict with anything?** No, and here's the actual reason: SQLite is file-locked, not port-bound. ECC's hooks are Node/shell processes that read/write their own state files. Prime Agent is a separate Python/IPython process entirely. None of them touch `~/.omniroute/*.db` — there's no shared table, no shared schema, no reason for two of these to ever open the same file. The only way SQLite conflicts with anything is if two *different* processes try to write the same `.db` file at once, and nothing else in your stack has any reason to touch OmniRoute's.

Where it *could* eventually collide is the same place I flagged for `reverse-skill` — OmniRoute's own MCP server (the 37-tool one on `localhost:20128`) sitting next to `code-review-graph`'s MCP server and anything else you register. That's a naming/port question, not a database one, and it's not live yet since only `code-review-graph` is registered.
