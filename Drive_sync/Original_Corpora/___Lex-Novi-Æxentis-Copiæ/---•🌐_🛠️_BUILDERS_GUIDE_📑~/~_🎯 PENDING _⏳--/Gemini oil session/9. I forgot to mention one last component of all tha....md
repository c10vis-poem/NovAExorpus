**OmniRoute** is the exact piece that unifies your entire distributed
topology.

Instead of hardcoding separate API keys, port addresses, and rate-limit
logic across your Moto Razr Ultra, Jetson Orin Nano, and Rubik Pi,
OmniRoute acts as a **single, local AI gateway**. By running a unified
OpenAI-compatible endpoint (typically served at
http://localhost:20128/v1), it abstracts your physical hardware and
cloud providers into a flexible, fault-tolerant proxy network.

## How OmniRoute Fits Into Your Architecture

### 1. Unified Entry Point Across the Tailnet

- Every CLI tool, script loop, and agent on your mesh sends requests to
  > one standard base URL (http://localhost:20128/v1).

- You don't need to reconfigure environment variables when switching
  > models or migrating tasks across nodes.

### 2. Intelligent "Combo" Strategies & Failover

- OmniRoute uses configurable routing chains ("combos").

- **Local-First Fallback:** You can set rules that route requests to
  > your local Snapdragon 8 Elite NPU via GenieX first. If the prompt
  > exceeds local context limits or hits thermal throttling, OmniRoute
  > silently cascades to your Jetson CUDA endpoint, Vertex AI, or cloud
  > backups in under a second—without breaking agent loop execution.

### 3. Built-In Token Compression (RTK & Caveman Engines)

- OmniRoute includes native token compression engines (like RTK) that
  > strip redundant payload overhead before hitting upstream models,
  > reducing context usage by **15–95%**.

- This keeps your structured JSONL Almanac logs and action trajectories
  > extremely lean before they land in your Red Agent audit queue.

### 4. Native MCP Server & Agent-to-Agent (A2A) Protocols

- OmniRoute acts as a Model Context Protocol (MCP) server. Your agents
  > can directly query the gateway via MCP tools to check provider
  > health, modify active routing combos on the fly, or inspect quota
  > remaining across endpoints.
