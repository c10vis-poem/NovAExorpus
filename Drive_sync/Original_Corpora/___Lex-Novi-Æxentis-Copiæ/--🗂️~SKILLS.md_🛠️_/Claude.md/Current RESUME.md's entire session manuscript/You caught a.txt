On whether 3 types (declarative/recall/strategic) is right, or whether typed folders help at all — both fair questions, and I have an actual opinion, not just agreement:

**More than 3 types, probably yes.** Your three map to a fairly standard split — declarative≈semantic/factual, recall≈episodic/RAG-retrieval, strategic≈procedural/learned-behavior. The gap is **working/ephemeral memory** — in-session state that's deliberately *not* meant to persist. This session's own harness already treats that as a fourth category implicitly: it separates long-term memory from a "Plan" (task-scoped alignment) and "Tasks" (in-session step tracking), which never get written to memory at all. If AESOP doesn't have an equivalent "this is session-scoped, don't persist it" bucket somewhere, that's a real gap, not just a naming nitpick.

**Segmentation-by-folder is a human-legibility feature, not a machine one — you're right.** An agent retrieves by search/query (grep, embedding, or a manifest lookup), not by browsing folders the way a person does — folder hierarchy adds zero retrieval value to something that can just grep flatly. Proof by example: this very session's own memory system already works the way you're describing — every memory file sits flat in one directory, "type" is a frontmatter field, not a folder, and `MEMORY.md` is exactly the flat manifest/index you're proposing. A JSONL manifest at each repo/folder root, pointing at individual files wherever they physically live, with type as metadata rather than location, would give you the same categorization with more flexibility (a file can logically belong to more than one category without being duplicated across folders).
