Let's lay out the entire production stack using industry-standard
engineering labels.

Because you are building a custom Kotlin APK that manages multiple
external layers, naming things precisely ensures your data models,
folder structures, and dropdown menus match exactly what these
technologies are. \[1\]

## **1. The Interaction Layer (The Interfaces)**

This is how a user (or another program) talks to your application stack.

- 

- **Front-End / UI:** **Your Jetpack Compose App Interface.** This is
  > the graphical layer responsible for rendering text tokens, buttons,
  > tool execution logs, and handling user inputs. \[2\]

- **CLI (Command Line Interface):** **An Access Trigger.** If you have
  > "different CLIs," these are labeled as **Target Shells** or
  > **Interface Channels**. For example, you might have an *ADB Shell
  > CLI*, a *Termux CLI*, or a *Local Dev CLI*. They all send strings to
  > the exact same app backend, but they act as different user-facing
  > doors. \[3, 4, 5\]

- 

## **2. The Coordination Layer (The Brain & Handler)**

This layer lives inside your APK process. It handles the continuous
logic loops. \[6, 7\]

- 

- **Harness:** **The Agent Orchestrator / Control Loop.** This is the
  > pure state machine logic wrapping the execution. It manages
  > conversation memory, dynamically builds prompts, truncates tokens,
  > intercepts text, and coordinates tool execution. \[7, 8\]

- **Back-End (Internal):** **The App Data Core.** In the context of your
  > APK, "the back-end" is your Kotlin background services, Room
  > Databases (for chat logs), and socket listeners. It handles the
  > heavy application-level lift behind the UI. \[9, 10, 11\]

- 

## **3. The Execution Layer (The Hardware & Math Drivers)**

This is where code actually runs and raw math equations are calculated
by silicon chips. \[1, 12\]

- 

- **Runtimes (Engine / Inference Runtimes):** **llama.cpp and QAIRT
  > (Qualcomm AI Runtime).**

  - You should absolutely label these as **Runtimes** (specifically,
    > **LLM Inference Engines** or **Hardware Acceleration Runtimes**).

  - They are software engines optimized to load heavy model binaries
    > (GGUF, DLC format) and process matrix math directly against the
    > CPU, GPU, or Qualcomm NPU hardware. \[1, 12, 13, 14, 15\]

- **Environment / Sandbox:** **The OS Sandbox.** This is the isolated
  > directory on Android (/data/user/0/...), a Docker container, or an
  > isolated Linux filesystem where file changes happen. \[16, 17\]

- 

## **4. The Networking Layer (The Infrastructure)**

This is how components pass data when they aren't compiled into the
exact same binary block.

- 

- **Servers:** **Network Enablers.** You only call something a "server"
  > if it is wrapped in an active network interface listening to a port
  > or socket. For example, if you configure llama.cpp to run as a local
  > web server (llama-server) hosting an API endpoint at localhost:8080,
  > that specific configuration is an **Inference Server**.

- **Back-End (External):** **Cloud APIs / Failbacks.** When talking
  > about agent architectures, an "External Back-End" refers to remote
  > cloud endpoints (like an Amazon CloudFront endpoint pointing to an
  > AWS Bedrock server or OpenAI API). It acts as your fallback
  > computing network if the device runs out of local VRAM. \[18, 19,
  > 20, 21, 22\]

- 

## **The Clean Labeling Matrix for Your UI Settings**

To make your Kotlin APK's settings menus clean and professional,
structure your configurations using these industry-standard
categorizations:

| Your Component                      | System Tier / Class       | Dropdown Label in Your UI        |
|-------------------------------------|---------------------------|----------------------------------|
| **Jetpack Compose Screens**         | Interface Layer           | UI View / Theme                  |
| **ADB / Termux / Custom Shell**     | Interface Channel         | Target CLI / Interface           |
| **Orchestration / Token Manager**   | Control Layer             | Agent Orchestrator (or Harness)  |
| **Llama.cpp (Local GGUF Executor)** | Hardware Inference Tier   | Local Inference Engine (Runtime) |
| **QAIRT (Qualcomm AI Runtime)**     | Hardware Inference Tier   | Hardware Accelerated Runtime     |
| **Llama 3 8B / Claude 3.5 Sonnet**  | Intelligence Tier         | Active Model Model Profile       |
| **WebView / Custom Sockets**        | Extension Tier            | MCP Tool Provider                |
| **CloudFront Failback Route**       | Cloud Infrastructure Tier | Remote Back-End Endpoint         |
