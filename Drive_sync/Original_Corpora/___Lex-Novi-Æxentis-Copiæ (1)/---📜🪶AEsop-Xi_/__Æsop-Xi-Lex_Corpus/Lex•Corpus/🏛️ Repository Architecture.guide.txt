Your file management system handles the physical data, while your memory layers handle how the AI interacts with that data.

🧠 The Three Cognitive Memory Types
The other two types of memory you were trying to think of are Semantic and Procedural (or State/Working) memory. Here is how all three break down:
* * Episodic Memory: Captures specific experiences or sequences of events. In an AI, this is the chronological chat history (e.g., "In message 4, the user said they are traveling to Japan next month").
* Semantic Memory: Handles generalized facts, concepts, and institutional knowledge divorced from a specific time or event (e.g., your company's product documentation, a coding language syntax, or a user's permanent profile preferences).
* Procedural Memory: Governs "how" to do things. For AI agents, this means remembering rules, workflows, system guidelines, and tool execution steps (e.g., knowing exactly what arguments to pass to an API tool when triggered).

📂 Example Codebase Structure
Here is how you can physically arrange these concepts in your directory:


src/
├── data_management/
│   ├── loaders.py            # Parses PDF, TXT, CSV files
│   └── database.py           # Connects to PostgreSQL, Pinecone, ChromaDB, etc.
│
└── memory_pipeline/
   ├── storage/
   │   └── saver.py          # Saves chat logs (Episodic) and updates user facts (Semantic)
   │
   ├── injection/
   │   └── context_loader.py # Fetches last session data to bootstrap the LLM prompt
   │
   ├── recall/
   │   └── search_engine.py  # Performs RAG / vector search mid-turn
   │
   └── types/
       ├── episodic.py       # Classes/schemas for raw message sequences
       ├── semantic.py       # Classes/schemas for facts, entities, and knowledge bases
       └── procedural.py     # System instructions and tool-calling schemas
