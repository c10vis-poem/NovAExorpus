## B2. What it does (one paragraph)
A per-project working-set router for coding agents. It treats each Markdown file (default scan `['**/*.md']`, router.py `from_directory` L104-105) as a node, discovers edges where one file mentions another, and keeps one scalar "pressure" per file. Each prompt activates files by word match, pressure spreads along edges, everything decays, a fixed global budget of 10 is enforced by a competitive tax, and the top files by pressure are injected as short slices (under 7,000 bytes). When the turn ends, the files the agent actually read or edited are reinforced, so pressure follows real use. No embeddings, no network, no database: state is JSON/JSONL files in `<project>/.hologram/`.

## B3. Algorithm, step by step (with file refs)
Per prompt (`hook prompt` -> `hooks_inject.build_layer` -> `router.process_query` -> `system.process_turn`):
1. Activation, `system.find_activated` (system.py L365-435). Query terms: lowercase, edge punctuation stripped, length >=3, no stop-words (`route_policy.query_terms`). Per file and word, first match wins: word in path 1.0; in title (first `#` line in the first 5 lines) 0.8; whole word in content 0.4; 4+ character prefix of a longer word 0.2. If at least 10 candidate files, a word found in more than 50% of them is dropped (`ACTIVATION_DF_MAX_SHARE=0.5`, `ACTIVATION_DF_MIN_FILES=10`); rarity weight `log((N+1)/(df+1))/log(N+1)` (`activation_idf`). Keep the best 8 (`activation_max_files`). Demoted paths (fixtures, testdata, eval_fixtures; `route_policy.DEMOTE_PATTERNS`, factor 0.1) are skipped unless the prompt names them (`DEMOTE_RELEASE_TOKENS`).
2. Activation boost, `pressure.apply_activation` L182-240: capped score `min(s,3)`; `total_boost = sum * 0.6`; with conservation that amount is drained equally from non-activated files; each activated file gets `learned_boost * min(score,3)` (per-file, default 0.6), ceiling `1.0 + 3*0.6` in "compete" mode.
3. Propagation, `pressure.propagate_pressure` L243-348: sources are files with raw pressure >= 0.8 (top 32 by pressure); BFS 2 hops; base flow 0.15 split over the node's outgoing edges (top 64 by edge weight), multiplied by edge weight and `0.7^(hop+1)`; the source loses what targets gain; result clamped to [0,1].
4. Decay, `pressure.apply_decay` L351-423: unless activated within 2 turns, `raw *= learned_decay ** (1/basin_depth)` (default decay 0.85). Basin depth `1.0 + min(consecutive_hot_turns/5,1)*1.5` (1.0 to 2.5): sustained HOT focus decays more slowly (0.85 -> about 0.94 at depth 2.5, per the docstring). `update_basin_state`: +1 per HOT turn, -2 when not HOT.
5. Budget, `pressure.redistribute_pressure` L457-510, mode `compete`: if total pressure exceeds 10.0, subtract the same tax from every file (zeroing files that run out), i.e. projection onto the budget simplex; the budget is a ceiling, never a target. Reason in the code comments: the older budget of 0.5 per file kept a 119-file project all lukewarm with nothing hot.
6. Tiers and working set. Pressure bucket = `int(raw*47)` of 48 buckets (coordinates.py L72-87); HOT bucket >=40, WARM 20-39, COLD <20. `working_set.select` (working_set.py L42-78) ignores buckets: rank by raw pressure, floor 0.25, 6 rendered (`HOLOGRAM_WORKING_SET_MAX`), next 10 named, filled by modification time up to 3 when fewer than 3 hold pressure ("never empty"); basenames deduped; `CLAUDE.md` copies skipped.
7. Injection, `hooks_inject.build_layer` L597-833: block `[HOLOGRAM] (cap=7000B, schema=t3-ctx/v1, project=...)`, `tier_counts`, then per file a typed slice (if YAML frontmatter `schema: t3-doc/v1`, slicers per type: architecture, snapshot, design, worklog, experiment, memo, todo, log, project-hub) or `[legacy/unknown]` + 300-char preview, plus up to 2 query-matched excerpts per file (lines with >=2 query tokens, in-document IDF), `next:` names, `bytes_used`. Whole hook output cap 9,000 bytes (`hook.py` OUTPUT_CAP), because Claude Code turns outputs over about 10 KB into a 2 KB preview. Route time budget 10 s via SIGALRM; a failure never blocks the harness.
End of turn (`hook stop` -> `hooks_observe.observe_turn`): read the harness transcript JSONL, take only the last turn (an earlier bug re-boosted old files every turn), `Read/Grep/Glob/NotebookRead` = used, `Edit/Write/MultiEdit/NotebookEdit` = edited, plus docs named by shell commands (`lexical.named_in_commands`: by path, or by a unique file name of 8+ characters); `router.observe` calls `process_turn` with those files as uniform-1.0 activation. This closes route -> use -> reinforce.
Learning: `learned_constants.learned_constants(used, seen, rate)` -> `lift = (used+1)/(seen*rate+1)`, boost = clamp(0.6*sqrt(lift), 0.4, 0.8), decay = 0.80 + 0.12*min(1, lift/2); project base rate `(used_total+1)/(seen_total+20)`. The Stop-hook learner that writes `t3_file_state.json` is not in the zip (unverified who writes it; `session.py` and `hooks_inject._apply_t3_state` only read it).
Session API (v0.3, `session.Session.turn`, used by CLI `hologram route`, NOT by the hook path): turn-state inheritance (`turn_state.py`: 60% of pressure >=0.3 carries to the next turn; tension accumulates 0.15 per unresolved query, decays 0.3; attention cluster of co-activated files), regex resolution detection (`resolution.py`: completion / topic change), auto-crystallization of a sustained cluster into a `sessions/<ts>_<slug>.md` note with auto `[[wikilinks]]` (`crystallize.py`).
Parked: toroidal "lighthouse" resurrection (`use_toroidal_decay=False`, parked 2026-10-05: it wiped the working set by resurrecting every dead file to 0.55 at once); `dynamic_budget` off.

## B5. How it maps vectors and graphs (the owner's question)
- It does not use vectors in the core. grep over `hologram/` and `tests/` finds no embedding code outside `hooks_inject.py` L455-547 (`_apply_predictor_rerank`), guarded by `edition.pro('learning')`; it loads Pro classes `T4RPredictor`, `ContentEmbedder`, `CoactivationMatrix` and weights `t3v4r_frozen.npz`, `.hologram_content_cache.npz` (SVD components over hashed-word embeddings: migrate.py L12 "built under the salted word hashing"), cosine = dot product of query and file embeddings, blended at most 30% into pressure. - Graph: the file mention graph (B4) plus pressure as a conserved scalar field on its nodes (pressure leaves a source when it flows to targets; global total capped at 10). A graph-diffusion model of attention, not a vector index.
